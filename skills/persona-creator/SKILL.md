# 角色创建技能（DSH 角色库三件套）

DSH 的角色库位于 `$DSH_HOME/personas/`（默认 `~/.dsh/personas/`）。一个完整角色 = 一个子目录 + 三个文件：

| 文件 | 用途 | 注入位置 |
|------|------|---------|
| `persona.yml` | 角色元数据：`name`（展示名）+ `description`（一句话简介） | 不进提示词，供列表/面板展示 |
| `SOUL.md` | 角色人格设定：身份、性格、语气、原则、边界 | 系统提示词的 `<soul>` 段落 |
| `USER.md` | 该角色专属的用户档案：称呼、偏好、沟通习惯 | 系统提示词的 `<user>` 段落 |

角色 id = 目录名（小写字母/数字/中横线，如 `meow-teacher`、`neko-companion`）。

## 两条路径

**A. 对话式创建（推荐）** —— 用本插件自带的 `persona` 工具，不碰文件路径：

```
persona action=create id=<id> name=<角色名> description=<一句话简介> soul=<SOUL.md 全文> user=<USER.md 全文>
```

- 只给 id/name/description 也可以：SOUL.md / USER.md 会落空白模板，之后再 `action=update` 补。
- 写完用 `persona action=use id=<id>` 设为当前角色。
- 修改已有角色用 `action=update`（可只传要改的字段）；`action=show` 读回三件套。

**B. 直接写文件** —— 角色库目录就在文件系统里，通用文件工具同样能读写。

> 两条路径等价。区别只在权限：文件工具受沙箱策略约束，`persona` 工具走进程内 `node:fs`，不受限。

## 工作流程

### 第 1 步：确定角色 id 与展示名

先问用户两件事：

- **角色名**：显示在角色列表里的名字
- **一句话简介**：用一句话描述这个角色（角色卡片的副标题）

然后定 id：英文小写 + 中横线（从角色名转写）；用户没偏好就自己生成并确认。

### 第 2 步：访谈收集

不要一次性抛一堆问题。按下面的顺序逐组提问，一次 1-2 个，用户回答完一组再问下一组。用户最初的描述已经覆盖某个主题时直接跳过。

**角色背景**：什么背景故事 / 什么身份（助教、伙伴、客服、导师……）？

**人格特质**：最突出的 3-5 个特质，每个都要写到「如何体现在对话里」（例：直接 → 看到废话直接打断，先给结论）。

**语气**：正式 / 随意 / 幽默 / 直率？简短结论还是详细讲解？出错、紧急、用户沮丧时语气怎样？

**原则**：必须遵守什么（如「优先保证准确，宁可明确说不确定」）？绝对不做什么？

**沟通风格**：怎么称呼用户？能用 emoji 吗？回复用什么格式？

**专业领域**：精通哪些领域，深度如何？

**边界**：有哪些不该触碰的话题或行为？

**用户信息**（进 USER.md）：用户怎么称呼？语言、沟通偏好、格式偏好？

### 第 3 步：生成三件套

#### 3.1 persona.yml

```yaml
name: <角色名>
description: <一句话简介>
```

#### 3.2 SOUL.md

用通用分节式模板，访谈内容原样填进去。用词必须是用户实际说过或明确认可的表述，不要凭空美化。标题行之后**直接开始 `## Identity`**，中间不加说明性注释。

```markdown
# SOUL.md — [角色名]

## Identity
[角色定位与背景，2-3 句具体描述]

## Personality
- [具体特质：描述它如何体现在对话里]
- [具体特质]

## Tone
- [语气倾向]且[语气倾向]
- [语言风格偏好]
- [回复长度偏好]
- [特殊场景的语气]

## Principles
- 永远[原则]
- 绝不[原则]
- 优先[价值观]

## Communication Style
- 称呼用户为[形式]
- [emoji 使用偏好]
- [格式化偏好]

## Expertise
- [领域]：[深度与使用方式]

## Boundaries
- 不做[边界]
- 避免[边界]
```

#### 3.3 USER.md

```markdown
# USER.md — [用户/主人档案]

## 基本信息
- 称呼：[怎么称呼用户]
- 语言偏好：[中文/英文/双语]
- 沟通风格：[正式/随意/简洁/详细]

## 偏好
- 格式偏好：[Markdown/纯文本/要点]
- 其他：
```

### 第 4 步：质量检查

交付前逐条对照，不满足就改：

- [ ] **具体性**：每个特质都写到「如何体现」——能否预测它对没聊过的话题的立场？
- [ ] **篇幅**：SOUL.md 不超过 100 行，50 行左右最好，核心放前面
- [ ] **边界**：Boundaries 至少 2 条禁令
- [ ] **不越界**：不含项目指令、临时风格、API Key 或密码
- [ ] **无元注释**：标题行下直接是 `## Identity`
- [ ] **id 合法**：小写字母/数字/中横线，角色库里不重复
- [ ] **USER.md 不空泛**：至少有称呼、语言、沟通风格三项

### 第 5 步：落库并告知生效时机

1. `persona action=create …`（或 `action=update …`）
2. `persona action=use id=<id>` 设为当前角色
3. 告诉用户：**角色在会话首条消息时固化进提示词**——当前会话不变，**新会话**才会用上；右侧栏「角色 / 记忆」面板可以查看和继续编辑

## 与记忆的分工

角色库和记忆是正交的两件事——**换角色不换记忆**：

| 位置 | 内容 | 作用域 | 谁来写 |
|------|------|--------|--------|
| `personas/<id>/` | `persona.yml` + `SOUL.md` + `USER.md` | 全局，同一时刻一个当前角色 | `persona` 工具 / 文件工具 / 面板 |
| `memory/FACT.md` | 长期事实（跨会话、跨项目） | 全局 | `memory` 工具 `action=update scope=global` |
| `memory/JOURNAL.jsonl` | 一次性事件 / 会话笔记 | 全局，仅追加 | `memory` 工具 `action=append`（`search` 检索） |
| `<项目根>/MEMORY.md` | 项目相关的稳定事实 | 随项目走 | `memory` 工具 `action=update scope=project` |

角色里**不要**写项目进度、临时任务、密钥——那些属于记忆，不属于人格。
